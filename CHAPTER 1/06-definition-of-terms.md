# Definition of Terms

The following terms are defined for consistent use in this report. Where a term has a broader professional meaning, the operational definition below states how it is used in the webinar report.

**AI-assisted software development.** The use of an artificial-intelligence tool to support activities such as code generation, completion, explanation, debugging, refactoring, or test creation. In this report, the term does not imply that the tool replaces developer review or testing.

**Continuous integration (CI).** A development practice in which changes are integrated frequently and automated checks such as builds, tests, linters, or security checks are run to detect problems early. In this report, CI is discussed as a possible part of the software workflow; whether it was demonstrated in the webinar is **[TO VERIFY]**.

**Evaluation instrument.** The form or structured set of questions used to collect participant responses about the webinar. The supplied CSV shows rating items, open-ended questions, consent fields, and attendance-evidence fields. Its validity and reliability are not assumed.

**Generative artificial intelligence (GenAI).** Artificial-intelligence systems that produce new content, including text or source code, in response to an input or prompt. The term is used here in connection with AI-assisted programming and is not treated as a guarantee of correctness.

**Participant evaluation.** A post-activity record of respondents' reported experience, ratings, comments, satisfaction, and perceived value. Participant evaluation is distinct from an objective assessment of learning or performance.

**Red-green-refactor.** A short TDD cycle in which a failing test is written first, a minimal implementation is added so that the test passes, and the code is then improved while the tests continue to pass.

**Software development engineer in test (SDET).** A role label used in this report for a software professional whose work combines programming with software testing, automation, debugging, and quality-focused engineering. The report does not claim that one universal job description applies to every organization.

**Software testing.** The planned and conducted activities used to evaluate software, obtain information about its quality, and identify defects, risks, or unmet expectations. The report uses the term broadly to include test design, execution, result interpretation, and communication.

**Test-driven development (TDD).** An iterative development approach in which automated tests are written before the corresponding implementation, followed by a cycle of making the test pass and refactoring the code. In this report, TDD is taught and discussed as a practice, not as a guaranteed cause of better learning or software quality.
